# 🏃‍♂️ プロダクト要件定義書 (SRD): Strava陣取りWebサービス

## 1. プロダクトビジョンと提供価値（勝つ意味）

- **コンセプト:** 日常のランニングルートを「可視化された陣取りゲーム」に変え、ランナーのコース開拓と継続的な運動モチベーションを創出する。
- **勝つ意味（インセンティブ）:**
- **仲間内での優越感:** 「〇〇さんがいつもの通勤ルートを奪いに来た」というActivity Logが、グループ内の強烈なコミュニケーションハブになる。
- **承認欲求の最大化:** 年末や月末に「獲得陣地数トップ」の美しいシェア画像（サイバーパンク風のマップなど）を生成し、StravaやSNSに投稿できる機能を提供することで、「勝って自慢すること」自体を目的化させる。

## 2. ゲームメカニクス（コアルール）

- **対象エリアと解像度:**
- Uber H3 インデックス（Resolution 7: 一辺約1.2km、面積約5㎢）を採用。

- **所有権と防衛（即時更新）:**
- Stravaにアクティビティがアップロードされた直後（Webhook経由）に、通過したタイル（点群が包含されるタイル）の所有権が**即時**にそのユーザーに移る。
- すでに自分が所有しているタイルを走った場合、タイルの「防衛」となり、スコア（色の濃さ）が100%にリセットされる。

- **スコアの減衰と視覚表現:**
- 所有権獲得時から**30日間かけて線形にスコアが減衰**（色が薄くなる）。
- スコアが0（30日経過）になると色は完全に消えるが、**ユーザーが設定した「アイコン」はゴーストとして残り続ける**（かつての栄華の証明）。

- **敗北とリセット:**
- 自分のアイコンが消える条件は以下の2つのみ。

1. 他人にそのタイルを走られ、奪われた時（即時）。
2. **毎年1月1日の「全体リセット」時**（全員がゼロからスタートし、新規参入者の壁をなくす）。

## 3. アプリケーション機能要件

- **認証・認可:** Strava OAuth連携（グループ招待リンク経由でのみ参加可能）。
- **マップビュー (メイン画面):**
- 「全体マップ（グループ全員の陣地とアイコンの混戦状態）」と「パーソナルマップ（自分の現在・過去の陣地のみ）」のトグル切り替え。

- **Activity Log (履歴画面):**
- 「〇〇さんが [エリア名] を奪取しました」「あなたの [エリア名] の色が消えかかっています」などのタイムラインを表示し、ブラウザ通知の代替とする。

- **プライバシー保護:**
- ユーザーが指定した座標・半径（例：自宅周辺500m）をプライバシーゾーンとし、その範囲内のGPSポイントは陣取り判定から除外する。

## 4. システムアーキテクチャ（完全無料・GitOps対応）

インフラコスト0円を維持し、Terraformでコード管理可能な構成。

- **フロントエンド & API Gateway:** **Vercel (Hobby Plan)**
- フレームワーク: Next.js (React)
- 役割: UIの提供、Strava OAuthのコールバック処理、Strava Webhookの受取（Serverless Functions）。

- **データベース & バックエンド:** **Supabase (Hobby Plan)**
- 役割: PostgreSQL + PostGISを利用した空間クエリ処理。
- 機能: ユーザーデータ、グループ情報、タイル所有権の永続化。H3ライブラリ（DB側またはVercel側）を用いてGPSの緯度経度からH3インデックスを算出・判定。

- **インフラ管理:** **Terraform + GitHub Actions**
- VercelプロジェクトとSupabaseプロジェクトのプロビジョニングをIaC化。

## 5. データベーススキーマ（基本構想）

Supabase (PostgreSQL) 上に最低限以下のテーブルを構築する。

1. **`users`**: Strava ID、表示名、設定アイコンURL、プライバシーゾーン（Polygonデータ）。
2. **`groups`**: グループID、グループ名。
3. **`group_members`**: ユーザーとグループの中間テーブル。
4. **`tiles`**: H3インデックス（主キー）、現在の所有者ID、最終更新日時（防衛・奪取のタイムスタンプ）。
5. **`activity_logs`**: ログID、対象グループID、アクション種別（奪取、防衛、減衰）、関連ユーザーID、メッセージ。
