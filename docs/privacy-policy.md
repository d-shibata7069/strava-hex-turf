# プライバシーポリシー（文書版）

本書は、Strava × H3 六角タイルの陣取り Web アプリ「strava-hex-turf」（以下「本サービス」）における、利用者のデータの取得・利用・保持・削除に関する方針を、審査提出・公開用に文書化したものです。

アプリ内のプライバシーポリシーページ（`/privacy`、文面は `client/messages/ja.json`・`en.json` の `privacy`）と矛盾しないよう作成しています。ただし、スコープに関する 1 点でアプリ内文面と実装実態に不整合があることが分かっており、その点は本書末尾の「既知の不整合と修正予定」に明記します。本書は実装実態に合わせて記載します。

> 開発ステータス: 本サービスは開発中であり、一般公開はしていません。現時点では Strava アプリの接続アスリート数の上限は開発者本人 1 人のみです。

## 1. 取得するデータと利用目的

本サービスは Strava API を通じて次のデータを取得し、記載した目的にのみ利用します。スコープ別の整理は [docs/README.md](README.md) の表が正本です。

| Scope | 取得データ | 利用目的 |
| --- | --- | --- |
| `read` | アスリートの公開プロフィール（表示名、プロフィール画像、Strava athlete ID） | ログイン中ユーザーの識別、グループ内での表示名・アイコン表示、ランキング表示 |
| `activity:read` | 公開アクティビティのメタデータ・GPS（距離、時刻、緯度経度系列） | H3 タイルの奪取／防衛判定、スコア計算、Activity Log 表示 |
| `activity:read_all` | 非公開アクティビティを含むアクティビティデータ | Webhook で受け取るアクティビティには非公開のものも含まれ、それらも陣取り判定の処理対象になるため、現在要求しています。あわせて `privacy_zone`（下記 5.）が設定されている場合は、そのゾーン内の H3 セルを領地化対象から除外します |

その他の取得・利用:

- **Strava のトークン:** OAuth 連携により取得したアクセストークン／リフレッシュトークンを、Webhook イベント発生時に該当アクティビティを取得するため、およびアカウント削除時に Strava 側の連携解除を行うために利用します。
- **本サービス内で生成するデータ:** グループ情報（グループ名、招待コード、所属関係）、タイル所有権、スコア、Activity Log、ユーザー設定（表示名、アイコン等）。これらは陣取りゲームの提供のために生成・利用します。
- **GPS の取り扱い（重要）:** アクティビティの GPS は、処理時に `summary_polyline` をデコードして H3 セル（Resolution 7）へ変換します。**生の GPS 系列（ポリライン）そのものはデータベースに保存しません。** 保存するのは H3 インデックス、タイルの所有者・スコア、`activity_tiles`（アクティビティとタイルの対応関係）、Activity Log などの派生データです。

上記データは、陣取りゲームの進行、グループ内でのランキング表示、Activity Log の表示にのみ利用し、これら以外の目的では利用しません。

## 2. 表示範囲

- タイル（陣地）、ランキング、Activity Log は、**同一グループのメンバー内でのみ**表示される設計です。
- グループに参加していないユーザーに対して、他ユーザーのタイルやログを表示する仕様にはなっていません。

## 3. 保存と保護方針

- 取得したデータは、本サービスのバックエンド（Supabase、PostgreSQL）において保存・管理します。
- **トークンの暗号化保存:** Strava のアクセストークン／リフレッシュトークンは、AES-256-GCM で暗号化してからデータベースに保存します。平文で保存する経路はありません。暗号化鍵が未設定の場合、トークンの保存は拒否されます。
- **アクセス制御:** データベースの全対象テーブルで Row Level Security（RLS）を有効化しています。タイル等の取得は、セッションとグループ所属（メンバーシップ）を検証する API 経由に限定し、匿名キーでの直接読み取りはできない状態をマイグレーションで保証しています。データベースへの書き込みは、原則としてサービスロールキーを持つバックエンドのみが行います。
- **通信:** アプリケーションとブラウザ、アプリケーションとバックエンドの通信は HTTPS を前提とします（本番の `BACKEND_API_URL` は `https` 必須）。内部 API 呼び出しには共有キーによる認証を行います。
- Strava から取得する権限は、本書 1. のスコープの範囲に限定しています。

## 4. 第三者提供の禁止

本サービスは、利用者の個人データおよびアクティビティデータを、第三者のマーケティングまたは商業目的で販売・貸与・共有しません。データは本サービスの運営および本ポリシーに記載した陣取りゲーム機能の提供にのみ使用します。

なお、本サービスはインフラとして Supabase（データベース）、Vercel（フロントエンドのホスティング想定）、GitHub Actions（日次バッチ実行）を利用します。これらは本サービスの運営に必要な範囲での委託・処理であり、マーケティング目的の提供ではありません。

## 5. プライバシーゾーン（`privacy_zone`）の扱い

- `privacy_zone` は、ユーザーの自宅周辺など、陣取り対象から除外したい範囲を表すポリゴン（`users.privacy_zone`、PostGIS Geometry）です。
- **バックエンドの実装状況:** ゾーンが設定されている場合に、その内側の H3 セルを領地化対象から除外する仕組みをバックエンドに実装済みです（Webhook 処理で適用）。ゾーン内のセルはタイルとして保存されません。
- **設定 UI の状況:** ゾーン設定用 UI は今後対応予定であり、現時点ではユーザーが画面からゾーンを設定する手段はありません。したがって現状、通常の利用で `privacy_zone` に値が入る経路はありません。
- `privacy_zone` のデータ自体は `users` 行に保存されるため、アカウント削除時にはプロフィール情報とともに削除されます（下記 6.）。

## 6. 保持と削除

### 6.1 保持の考え方

- プロフィール、グループ所属、タイル所有権、スコア、Activity Log 等は、アカウントが存続する間、ゲームの進行のために保持します。
- スコアはゲームルールとして獲得・防衛から 30 日で 0 まで減衰しますが、これはスコア値の減衰であり、タイルレコード自体の自動削除を意味するものではありません。

### 6.2 アカウント削除時

- ユーザーは、アプリ内の設定画面から自らのアカウントを削除できます。
- アカウント削除では、まず保存済みトークンを用いて Strava 側の OAuth 連携解除（deauthorize）を試行します（成功・失敗にかかわらず退会処理は続行します）。
- その後、`users` 行を削除します。外部キー制約により、関連するプロフィール情報、`privacy_zone`、暗号化保存されたトークン、グループ所属（`group_members`）、タイル（`tiles`）、`activity_tiles`、Activity Log（`activity_logs`）、日次統計（`user_group_daily_stats`）は連動して削除（ON DELETE CASCADE）され、復元できない状態にします。
- 削除後はセッション Cookie も破棄します。

### 6.3 Strava 連携解除時（deauthorization）

- ユーザーが Strava 側で本サービスとの連携を解除すると、Strava Webhook の連携解除イベント（`object_type=athlete`、`updates.authorized=false`）を受信します。
- バックエンドは、ペイロードの `authorized` が `false` であることを確認したうえで、`owner_id`（Strava athlete ID）に対応する `users` 行を削除します。これにより、上記 6.2 と同様に、関連データも外部キー制約で連動して削除されます。
- 対象ユーザーが存在しない場合は、削除を行わず正常終了として扱います。

### 6.4 Strava 側でアクティビティが削除された場合

- Webhook のアクティビティ削除イベントを受信した場合、当該アクティビティ由来の `activity_tiles` を削除し、影響を受けたタイルの所有権を残りのアクティビティから再計算します。

## 7. ユーザーの同意について

本サービスを利用することにより、本プライバシーポリシーに記載したデータの取得・利用・保存に同意したものとみなします。Strava の認可画面で、本サービスが求めるスコープを許可していただく必要があります。同意いただけない場合、本サービスはご利用いただけません。

## 8. ポリシーの改定

本ポリシーは、法令の変更やサービス内容の変更に応じて改定することがあります。重要な変更がある場合は、アプリ内または適切な方法でお知らせします。

## 既知の不整合と修正予定（審査提出前に解消すること）

- アプリ内プライバシーポリシーページの文面（`client/messages/ja.json`・`en.json`）およびログイン画面の説明文には、「本サービスは `read` と `activity:read` のみを利用し、`activity:read_all` は現在要求していません」という趣旨の記述が残っています。しかし実装実態は、認可ルート（`client/app/api/auth/strava/login/route.ts`）が `read,activity:read_all` を要求しており、[docs/README.md](README.md) のスコープ表も「`activity:read_all` は現在要求している」と整理しています。
- したがって**アプリ内文面のほうが古く、実態と一致していません**。本書は実装実態に合わせて記載しましたが、公開・審査提出の前に、アプリ内文面（プライバシーポリシー、ログイン説明）も実態に合わせて修正する必要があります。残件として [docs/launch-checklist.md](launch-checklist.md) にも記載しています。
